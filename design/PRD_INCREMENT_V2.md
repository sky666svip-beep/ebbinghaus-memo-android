# PRD 增量 V2 · 数据安全 + 列表效率 + 工程打磨

> 作者：产品经理 许清楚 ｜ 范围：**仅本次 6 项增量（E01/E02/E06/E10/E11 + Batch 3）**，不含实现代码
> 依据：`ORIGINAL_REQUEST.md`(R1~R4)、`design/ENHANCEMENT_BACKLOG.md`(E00~E17)、`design/OPTIMIZATION_ROADMAP.md`(D01~D17 / Batch 3)、`design/DELIVERY_SUMMARY.md`
> 基线：`./gradlew test` 84 passed；debug 16.7 MB / release(R8) 1.53 MB；minSdk 26，compileSdk/targetSdk 35（**不升 36**）
> **红线（唯一裁判标准）**：轻量、离线优先、零冗余权限、不引入冗余大型三方库。任何冲突项一律降级或不做。

## 1. 产品目标

**一句话**：让用户"敢投入、删不错、找得到"——把当前**唯一不可逆的资产损失风险**（卸载/误删即归零）补上，同时补齐列表的组织效率，并把启动与工程结构打磨到可长期维护。

三个正交目标：

1. **资产可保全**：数据从"卸载即 100% 丢失"变为"可导出、可导入、可自动快照"（E01/E02）。
2. **误删可挽回**：删除从"物理删除 + 级联抹进度"变为"软删除 + 可还原"（E06），并让批量整理不再危险（E11）。
3. **效率与体感**：列表按需排序（E10），冷启动更快（Baseline Profile + 启动惰性化），工程边界清晰（`:core` 模块化）。

> 本迭代**唯一触发 Room 迁移**的是 E06；E01/E02/E10/E11 与 Batch 3 **全部零迁移**。

## 2. 用户故事

### E06 回收站（持久软删除）
- 作为用户，我希望删除知识点时它先进回收站而不是彻底消失，以便发现删错时还能找回。
- 作为用户，我希望在回收站里一键还原某个知识点，以便连它的笔记和复习进度一起恢复。
- 作为用户，我希望回收站自动清理过期条目，以便它不会无限膨胀。
- 作为用户，我希望被删除的知识点不再出现在复习队列里，以便不复习已删内容。
- 作为用户，我希望还原后复习进度与删除前完全一致，以便我的复习投入不白费。

### E10 列表排序选项
- 作为用户，我希望按创建时间/更新时间排序，以便按录入或修改顺序浏览。
- 作为用户，我希望按复习档位排序，以便优先关注高投入（高价值）的知识点。
- 作为用户，我希望按到期日排序，以便提前看清接下来几天要复习什么。
- 作为用户，我希望排序选择重启后仍然生效，以便不用每次重设。
- 作为用户，我希望切换排序时不丢失我当前的搜索词与标签筛选。

### E11 批量操作（多选）
- 作为用户，我希望长按列表项进入多选态，以便连续勾选多条。
- 作为用户，我希望多选后一次性批量删除，以便快速清理且不必逐条确认。
- 作为用户，我希望多选后一次性批量打标签，以便批量归类。
- 作为用户，我希望看到"已选 N 条"并支持全选/取消全选，以便操作可控。
- 作为用户，我希望随时退出多选态，以便误入后能立刻回到正常浏览。

### E01 全量数据导出/导入（JSON）
- 作为用户，我希望把全部数据导出成一个 JSON 文件，以便换机/重装前留底。
- 作为用户，我希望在新设备上导入该文件即完整还原，以便多年积累不丢。
- 作为用户，我希望导入前被告知将要发生什么（覆盖还是合并、多少条），以便不误操作。
- 作为用户，我希望文件带版本号，以便版本不兼容时得到明确提示而不是静默出错。
- 作为用户，我希望导出/导入不申请存储权限，以便不牺牲本 App"零权限"的定位。

### E02 自动本地快照
- 作为用户，我希望 App 自动把数据快照到我指定的目录，以便忘记手动导出时仍有兜底。
- 作为用户，我希望快照失败时能收到提示，以便我知道兜底已失效。
- 作为用户，我希望快照在后台完成，以便不打断我的操作。
- 作为用户，我希望只保留最近若干份快照，以便不占满存储。

### Batch 3 · 工程类
- 作为用户，我希望冷启动更快，以便打开即用（Baseline Profile：目标 −15%~−30%）。
- 作为用户，我希望首屏不因初始化而卡顿，以便交互跟手（启动惰性化：`onCreate` 改 `by lazy`）。
- 作为开发者，我希望 `core/` 成为独立 Gradle module，以便编译期边界清晰、增量编译更快、算法层可独立测试。

## 4. 交互与 UI 设计要点

### 4.1 回收站入口
- **入口位置：设置页新增"数据与安全"分组内的"回收站"项**（设置页已是底部第 3 个 Tab，天然承载低频功能）。
- **不在列表页菜单放回收站入口**：列表页 `TopAppBar` 需保持干净以容纳新增的"排序 + 多选"操作，低频的回收站不应占用高频区。
- 回收站为**独立下钻页**（不占 Tab）：列表项展示内容摘要 + 标签 + "删除于 X 天前 / 剩余 Y 天"，右侧"还原"按钮；支持"清空回收站"（二次确认）。
- 空态复用 `EmptyState`（文案："回收站是空的"）。

### 4.2 批量操作（多选）
- **进入**：在列表卡片上**长按**进入多选态（与现有"点击进详情"不冲突，手势层级不同）。
- **多选态外观**：`TopAppBar` 切换为"已选 N 条 + 关闭"；底部 `NavigationBar` 被**操作栏**替换，含「删除」「打标签」「全选/取消全选」。
- **退出**：点击"关闭"或系统返回键退出并清空选择；操作完成后自动退出多选态。
- **批量删除**：一次确认弹窗（文案含条数），复用 `DeleteConfirmDialog` 并补充"删除后可到回收站还原"说明——这是 E06 带来的**文案变更点**（原为"级联清除进度"的不可逆提示）。
- **批量打标签**：底部弹窗输入/选择标签，去重合并；结果以 Snackbar 反馈"已为 N 条添加标签 X"。

### 4.3 排序选项
- **形态：底部弹窗（`ModalBottomSheet`）**，单选列表 4 项，当前项带勾选。
- **入口**：列表页 `TopAppBar` 右侧"排序"图标按钮（`Icons.AutoMirrored.Filled.Sort`），与搜索栏分离——排序是"视图状态"，搜索是"内容过滤"，语义不同层。
- 选择即时生效并持久化；弹窗内不出现"应用/确定"按钮（点击即生效，符合轻量原则）。

### 4.4 导出 / 导入 / 快照
| 能力 | 入口 | 交互与反馈 |
|---|---|---|
| 导出 | 设置页 · 数据与安全 · "导出数据" | 点击 → SAF `CreateDocument`（默认名 `ebbinghaus-YYYYMMDD.json`）→ 进度（条目少时可瞬时，>500 条显示不确定进度条）→ 成功 Snackbar "已导出 N 条"；取消选择不提示 |
| 导入 | 设置页 · 数据与安全 · "导入数据" | 点击 → SAF `OpenDocument` → **先解析并展示预览弹窗**（"将导入 N 条知识点 / M 条复习记录"）→ 用户确认 → 执行 → 结果 Snackbar（成功条数 / 失败原因） |
| 自动快照 | 设置页 · 数据与安全 · "自动快照" | 开关 + "选择快照目录"（SAF `OpenDocumentTree`，持久化 URI 授权）+ 保留份数选择；开关开启但未选目录时**不允许开启**并提示 |
| 失败提示 | 统一 Snackbar | 文案区分：文件损坏 / 版本不兼容 / 目录不可写 / URI 授权失效；**均不崩溃** |

> **零权限约束**：以上全部走 SAF，**不申请 `READ/WRITE_EXTERNAL_STORAGE`、不使用 `MANAGE_EXTERNAL_STORAGE`**，不新增 `FileProvider`（无需分享场景）。

### 4.5 与现有「搜索 + 标签筛选 + 三档响应式」的共存（关键，不得互相打架）

**唯一数据流原则**：`搜索词`、`标签筛选`、`排序` 三者都是列表查询的**输入参数**，必须收敛到**同一条查询管线**（DAO 层组合 WHERE + ORDER BY），**不得**做成"筛选后再内存排序"的叠加补丁。

| 交互 | 共存规则 |
|---|---|
| **排序 × 搜索/标签筛选** | 排序只改变 `ORDER BY`，**不参与过滤**；三者可同时生效（"标签=X + 关键词=Y + 按档位排序"）。切换排序**不得**清空搜索词或标签选中态 |
| **搜索/筛选 × 回收站** | 回收站是**独立查询域**（`deletedAt IS NOT NULL`），不复用列表页的搜索/筛选状态；进入回收站时列表页的搜索词与标签**保持原样**（返回后不丢） |
| **多选态 × 搜索/标签筛选** | 进入多选态后，**搜索栏与标签栏置灰禁用**（避免"选择集"随筛选变化而语义不清）；退出多选态后恢复可用 |
| **多选态 × 响应式三档** | Compact：操作栏替换底部 `NavigationBar`；Medium/Expanded：操作栏替换 `NavigationRail`（或置于 TopAppBar 下方）；**Expanded 双窗格**下多选态**作用于左 Pane 列表**，右侧详情 Pane 保持可见但禁用编辑，退出多选态后恢复 |
| **排序 × 双窗格** | 排序为**左 Pane 的视图状态**，由 `MemoListViewModel` 持有（单一数据源），单列与双窗格共享同一排序值，切换断点时保持一致 |
| **回收站 × 复习 Tab** | 软删除条目**必须**从复习队列与今日待复习计数（含底部 Badge）中消失，三处口径同源（见 §5-1） |

## 5. 边界与异常场景

1. **软删除与复习调度（关键）**：被软删除的知识点**必须从复习队列消失**，且不计入"今日待复习量"与底部导航 Badge。实现口径：`ReviewTaskDao` 的 `INNER JOIN` 查询增加 `WHERE m.deletedAt IS NULL`；**三处（复习页 / 看板 / Badge）必须共用同一查询**，不得各写一份过滤。还原后该条**重新进入队列**；若其 `dueDate` 已过期，按 R2「免惩罚」原则正常进入当日队列，**不标记逾期**。
2. **删除时复习进度保留**：软删除**不删除** `review_tasks` 行，因此"还原即恢复进度"是天然结果，而非额外补偿逻辑。
3. **回收站超期**：超过保留天数的条目在**应用启动时**（复用现有"同日去重"式检查）批量物理删除，连带 CASCADE 清除 `review_tasks`；清理在 IO 线程执行，失败不影响启动。
4. **回收站内重复删除**：对回收站条目再次删除 = 立即物理删除（需二次确认），文案明确"不可恢复"。
5. **批量操作中途取消**：整批在**单事务**内提交；用户取消或进程被杀 → 全部回滚，不产生"删了一半"的状态。
6. **批量打标签遇到重复**：目标标签已存在于某条 → 跳过该条，不产生重复项（`tags` 为 `U+001F` 分隔单列，需去重后回写）。
7. **导出时数据为空**：仍生成合法 JSON（含 `schemaVersion`、空数组），提示"已导出 0 条"，**不报错、不崩溃**。
8. **导入损坏 JSON**：解析失败 → 提示"文件已损坏或不是本 App 的导出文件"，**不写入任何数据**（先全量解析校验、后落库）。
9. **导入版本不兼容**：`schemaVersion` 高于当前支持版本 → 明确提示"文件来自更新版本，请升级 App"，**不尝试部分导入**；低于当前版本 → 走既定升级路径或提示不支持（见 §6-3）。
10. **导入写入失败**：落库在单事务内完成，任一条失败则整体回滚并提示，**不产生半量数据**。
11. **快照目录不可写 / URI 授权失效**：捕获异常 → Snackbar 提示并**自动关闭自动快照开关**（避免静默失效后用户误以为有兜底）。
12. **快照保留份数超限**：按文件名日期排序，删除最旧文件；删除失败仅记录，不阻塞新快照。
13. **搜索/标签筛选下进入多选**：见 §4.5——多选态下筛选控件置灰，退出后恢复，避免选择集漂移。
14. **迁移失败兜底**：仅使用 `fallbackToDestructiveMigrationOnDowngrade()`（降级场景），**绝不使用**全量 `fallbackToDestructiveMigration()`（会静默清空用户数据）。
15. **Baseline Profile 与代码漂移**：profile 与代码强相关，若关键路径改动导致失效，**不得**为凑指标引入额外依赖；仅记录并重录。
16. **`:core` 模块化回归**：抽取后若 `:core` 出现任何 Android 依赖（如误引 `androidx.*`），视为验收失败；包名必须保持不变以避免全项目 import 变更。
