> 作者：产品经理 许清楚 ｜ 范围：**仅本次 10 项（P2-1 ~ P2-10）**，不含实现代码
> 依据：`design/INTERACTION_REVIEW.md`（§四 P2 表 / §五 增强建议 / §六 修复顺序）
> 基线：`./gradlew test` = **175 passed / 0 failed**；debug ≈17.8 MB / release ≈1.65 MB；minSdk 26，compileSdk/targetSdk **35（不升 36）**
> **红线（唯一裁判标准）**：轻量、离线优先、零冗余权限、不引入冗余大型三方库；`AndroidManifest` 零新增权限、零新增依赖；保持「免惩罚」文案（禁用「逾期/失败/落后」，统一「顺延/待复习/已移入回收站」）

## 1. 产品目标

**一句话**：把「点了没反应、说的和做的不一样、删错了救不回」这三类**信任磨损**清掉——消除全部交互死区与语义不一致，并把回收站从「只能看和还原」升级为「可预览、可搜索、可批量管理」。

三个正交目标：

1. **无死区**：凡有涟漪/可点的元素必有确定动作（P2-5 标签 Chip），凡有信息冗余/歧义的文案必须与真实语义一致（P2-7「全选」、P2-9「达成」、P2-6 上限）。
2. **误删可挽回**：删除从「唯一出口是三层深的回收站」变为「5 秒内就地撤销」（P2-1），且回收站内可预览判断、可批量处置（P2-2/P2-3/P2-4）。
3. **口径一致**：搜索切分、标签输入两处「同类交互不同实现」收敛为统一口径（P2-8/P2-10），杜绝「高亮结果 ≠ 筛选结果」。

> 本迭代**不触碰 Room schema**（无迁移、无新表、无新列）；仅 P2-3/P2-4 需**新增只读/批量 DAO 方法**（无 schema 变更）。

## 2. 用户故事

### P2-1 删除后撤销
- 作为用户，我希望删除后 5 秒内能一键撤销，以便手滑时立刻救回，而不用进设置翻三层找回收站。
- 作为用户，我希望批量删除后也能一次撤销整批，以便误删一批时不逐条还原。
- 作为用户，我希望撤销窗口结束后提示「已移入回收站，可在设置中还原」，以便知道还有兜底路径。

### P2-2 回收站预览
- 作为用户，我希望点击回收站条目就能就地看到完整内容，以便内容相似时判断该还原哪条。
- 作为用户，我希望预览里能看到笔记与标签，以便靠上下文确认是我要的那条。
- 作为用户，我希望预览里能看到复习进度（档位/下次到期/已复习次数），以便知道还原它能救回多少投入。

### P2-3 回收站批量操作
- 作为用户，我希望在回收站长按进入多选，以便一次还原或彻底删除多条。
- 作为用户，我希望批量彻底删除前有二次确认并告知条数，以便不误清空。
- 作为用户，我希望批量还原无需繁琐确认、直接完成并提示，以便高效恢复。

### P2-4 回收站搜索/排序
- 作为用户，我希望在回收站按关键词搜索，以便条目多时快速定位。
- 作为用户，我希望回收站能切换排序（删除时间倒/正序、按标签），以便按我的习惯浏览。
- 作为用户，我希望回收站的搜索/排序不干扰列表页的搜索词与筛选，以便返回后原样保留。

### P2-5 标签 Chip 筛选
- 作为用户，我希望点击卡片上的标签即按该标签筛选，以便从一条内容直接跳到同类集合。
- 作为用户，我希望筛选后列表回到顶部并显示当前筛选条件，以便看清结果从哪来、能一键清除。

### P2-6 搜索 6 词上限提示
- 作为用户，我希望输入超过 6 个关键词时被轻提示，以便知道哪些词没生效，而不是以为搜错了。

### P2-7 「全选」语义
- 作为用户，我希望「全选」按钮文案明确它是「全选当前结果」，以便清楚选择集范围（当前筛选结果，而非全部数据）。

### P2-8 标签输入一致
- 作为用户，我希望编辑器里既能自由输入新标签，也能从已有标签点选，以便打标签体验与批量打标签一致。

### P2-9 `dailyLimit = 0` 语义
- 作为用户，我希望上限设为 0 时看到「今日已按设置暂停复习」而非「🎉 达成」，以便理解这是我的设置而非系统判断。
- 作为用户，我希望该状态有一个直达设置页的入口，以便随时恢复复习。

### P2-10 切分口径统一
- 作为用户，我希望搜索高亮的词与真正参与筛选的词完全一致，以便所见即所得。

## 4. 交互设计要点（决策结论）

### 4.1 P2-1 撤销
- **窗口时长：5 秒**（`SnackbarDuration.Long` 实为 10s，需显式 `withDismissAction` + 自定义 5000ms 超时；建议用 `SnackbarHostState.showSnackbar(..., duration = Short)` 配合状态位，**不引入新依赖**）。
- **单条撤销 = 只还原刚删的那一条**（`restoreMemo(id)`）；**不**提供「还原本批次」之外的额外语义。
- **批量删除后撤销 = 还原本批次全部**（`restoreMemos(ids)`，单事务），与「批量」的操作粒度对称。
- **Snackbar 只显示一次，连删两条 = 后者覆盖前者**：新删除的 Snackbar 立即替换旧的，**旧撤销回调失效**（避免「撤销了哪一批」的歧义）。实现口径：撤销目标以「最近一次删除的 id 集合」单值持有，新删除覆盖旧值。
- 超时后不追加操作，仅由回收站承接兜底（P2-1 与 E06 互补，**不重复实现**）。

### 4.2 P2-2 预览
- **就地展开**（卡片内 `animateContentSize`），**不弹窗不跳页**——与列表卡片展开手感一致，且天然支持「同时展开多条对比」。
- 展开后展示：**完整内容**（Markdown/LaTeX 走既有 `MathView`）+ **笔记** + **标签** + **复习进度**（档位 `stageLevel` / 下次到期 `dueDate` / 已复习次数 `reviewCount`）。
- 折叠态保持 3 行摘要 + 标签 + 「删除于 X 天前 · 剩余 Y 天」。

### 4.3 P2-3 批量
- **复用列表页多选交互**：长按进入多选态、顶部「已选 N 条」、底部操作栏（还原 / 彻底删除 / 全选 / 关闭）、系统返回键退出（沿用 P0-3 上提的 `BackHandler` 思路，作用于回收站路由）。
- **批量还原：无需二次确认**，直接执行 + Snackbar「已还原 N 条，复习进度一并恢复」。
- **批量彻底删除：必须二次确认**，弹窗文案「将彻底删除 N 条知识点及其复习任务，此操作不可恢复。」（复用现有 `AlertDialog` 红色确认样式）。
- 多选态下**禁用搜索栏**（避免选择集随筛选漂移，与列表页 §4.5 规则一致）。

### 4.4 P2-4 搜索排序
- **排序选项 3 项**：删除时间倒序（默认）/ 删除时间正序 / 按标签。**不提供**按档位/到期日（回收站语义是「管理」而非「复习」）。
- **搜索范围 = 内容 + 笔记 + 标签**（与列表页口径一致，切分规则同 P2-10）。
- 形态：顶部搜索栏（同列表页样式）+ 右上角排序图标 + `ModalBottomSheet` 单选，点击即生效。
- **独立查询域**：进入/离开回收站不清空、不写入列表页的搜索词与标签状态。

### 4.5 P2-5 标签 Chip
- **点击 = 筛选**（非追加到搜索框）：因为用户预期是「看同类」，且筛选是可一键清除的可逆动作。
- 点击后：① 以该标签作为 `tag` 参数筛选；② 列表 `scrollToItem(0)` **回到顶部**（结果集整体变化，保留旧滚动位置会误导）；③ 顶部出现「标签：T」可清除指示（清除即回到筛选前结果）。

### 4.6 P2-6 6 词上限
- **保持 6 词上限**（无上限需动态拼接 SQL，触碰数据层且有注入面；当前参数化 6 元方案**零注入风险**，不动）。
- 提示方式：**搜索框下方一行 `labelSmall` 辅助文字**，仅在超限时出现——不弹 Snackbar、不遮挡列表，**不打扰**。
- 文案：「最多支持 6 个关键词，已忽略多余 N 个」。

### 4.7 P2-8 标签选择器
- **混合模式：文本框为主 + 候选 Chip 为辅**——既保留「自由输入新标签」（原能力不丢），又补上「从已有标签点选」（与批量打标签一致）。
- 候选 Chip 点击 = **追加**到文本框（不是替换），自动去重；文本框仍按 `split(",", "，", "、", " ")` 解析为 `List<String>` 并去重去空。
- **不改为**单值 `TagPickerDialog`（编辑器需支持多标签，单值选择器会削弱能力）。

### 4.8 P2-9 `dailyLimit = 0`
- 展示「**今日已按设置暂停复习**」+ 说明「复习上限为 0，可在设置中调整」+ **「去设置」入口**（直达设置页每日上限分组）。
- `dailyLimit > 0 且队列空` 仍显示原「🎉 今日复习全部达成！」——两者分支**必须区分**，避免误伤正常达成场景。

## 5. 边界与异常场景（≥10）

1. **撤销时该条已被其他操作修改**：撤销仅恢复 `deletedAt`（置 NULL），**不覆盖** `content/notes/tags`——即还原后保留删除后的最新编辑，不产生「回滚用户后续修改」的意外。
2. **撤销时该条已过期被清理**：若期间应用启动触发了 `purgeExpiredTrash` 已物理删除该 id，撤销为**无操作**，Snackbar 提示「该条目已过期，无法还原」；**不崩溃**。
3. **连删两条 + 撤销**：仅最新一条（批）可撤销；对旧批次的撤销回调**已失效**，不会误还原无关条目。
4. **批量还原中途失败**：单事务内任一失败 → 整体回滚，Snackbar「操作失败，请重试」，**无半还原状态**。
5. **回收站预览中条目被超期清理**：预览展开期间该条被清理 → 列表流刷新后该项消失，展开态随之卸载；**不残留悬空状态、不崩溃**。
6. **回收站搜索无结果**：复用 `EmptyState`，文案「没有匹配的知识点」+「清空搜索」CTA；与「回收站是空的」文案**区分**。
7. **标签 Chip 点击时该标签已不存在**（如他处编辑已删除该标签）：点击后筛选结果为「无匹配」空态，**不崩溃**；指示条仍显示「标签：T」供清除。
8. **6 词上限边界**：恰好 6 词 → **不提示**；7 词 → 提示「已忽略多余 1 个」；全空格/仅分隔符 → 切分后 0 词，视为**无关键词**（`k1..k6` 全空串），**不提示**、**不报错**。
9. **切分口径边界（P2-10）**：输入含全角空格 `　` / 换行 `\n` / Tab `\t` 时，UI 高亮词集合与仓储查询词集合**必须相等**（断言前 6 个）；单行输入框粘贴多行文本不应产生「高亮 2 词、实际按 1 词筛选」。
10. **`dailyLimit = 0` 且回收站有条目**：复习页显示「暂停复习」分支；**不影响**回收站功能与 Badge（Badge 在 `dailyLimit<=0` 时本就隐藏，保持现状）。
11. **多选态下回收站条目被外部清理**：选择集与 `current.items` 求交，已消失的 id 从选择集中剔除，避免「已选 N 条」与实际不符。
12. **就地预览 + 长按多选手势冲突**：长按进多选、单击展开，二者手势层级不同，**不得互相吞没**（多选态下单击 = 切换勾选，不再展开）。
